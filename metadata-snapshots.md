# Metadata snapshot admission

The metadata value language is closed. Admission must inspect an input's kind before structural copying can erase it. A function or Map becoming an empty record is not validation. Defaults, computed builders, conversion-factor snapshots and reflected construction share the same snapshot boundary. Declaration publication remains as specified in [meta-publication.md](meta-publication.md).

## Kind admission and reflection

| Direction | Ergonomics and autocomplete / wrong guesses | Prior art, including Rust | Production performance / shapes and ICs | Correctness and reference liveness | Other / decision |
| --- | --- | --- | --- | --- | --- |
| Copy enumerable properties from every object | A suggested callable or collection silently becomes a different value; mistakes can intern unrelated types together | Rust admits structs and function paths in some const contexts, but does not erase one kind into another. JSON's lossy projection is not a type-identity contract | Simple traversal, unsound canonical keys and specialization assumptions | Violates the closed language and grants no reference evidence | Reject |
| Reject all object-valued metadata | Removes records, lists, ranges and patterns from normal usage; completions describe values callers cannot supply | Rust const aggregates show why a blanket aggregate ban is too broad; its exact value language is different | Cheap rejection but prevents useful canonical descriptor specialization | Contradicts already supported forms | Reject |
| Trust public tags such as __range or user coercions | Ordinary member names unexpectedly change the kind; getters may run only because the engine guessed a tag | ECMAScript internal slots distinguish builtin payloads; Rust nominal kinds do not use arbitrary dynamic property names as authority | Extra user calls and shape/IC dependencies for what should be a kind test | Forged tags can bypass recursive leaf admission; no liveness fact follows | Reject |
| Admit actual supported kinds, then snapshot their prescribed data | Reflected values expose useful Array/RegExp/Range members; errors identify unsupported inputs without destroying their meaning | Rust's explicit const-expression/value rules motivate checking admission, not importing its supported kinds. ECMAScript supplies object/internal-method distinctions | Engine kind tags plus compiler-owned canonical descriptors; no user-object fields or shape changes. Materialize at reflection/hook boundaries | Preserve numeric domains, Symbol identity, range shape and pattern data; reject functions, undefined, unsupported objects and cyclic graphs. Reference permissions stay separate | Recommend independently of implementation effort |

Record inputs are ordinary objects with ordinary property access, without construction identity, private elements or opaque payload slots. Object-literal, null-prototype and ordinary Object.create records qualify; their prototypes do not contribute fields. Class instances, boxed primitives, collection objects, typed-array objects and Proxies do not acquire record status by changing their prototypes. Actual supported numeric atoms, ranges and patterns are recognized by their engine kind before record handling. No Proxy trap, public tag lookup or coercion participates in deciding kind admission.

Reflection must use the same value materializer as hooks. A list is presented as an Array, a pattern as a RegExp and a range as a Range value. Public implementation-marker records are not the interchange contract. This also removes the speculative Get of __range from every ordinary record, including inherited or nonenumerable getters that the record projection should never read.

## Lists, records and observable reads

| Direction | Ergonomics and autocomplete / wrong guesses | Prior art, including Rust | Production performance / shapes and ICs | Correctness and reference liveness | Other / decision |
| --- | --- | --- | --- | --- | --- |
| Enumerate Array properties and append their values | Holes compact, nonenumerable indices vanish and named properties become extra elements; indexed completions misdescribe the result | Rust arrays have positional length, not property enumeration. Ordinary ECMAScript Array indexing also differs from own-key enumeration | Cheap enumeration but loses canonical length/index invariants | Violates list length/order and can hide undefined; supplies no reference permission | Reject |
| Forbid getters, sharing, nonenumerable indices and every nonliteral producer | Unnecessary rewrites and confusing origin-dependent acceptance | Rust's restricted effects do not establish a JavaScript literal-only rule; this proposal already executes eligible helpers/getters | Simplifies one implementation at the cost of expressiveness, with no inherent shape benefit | Conflicts with existing snapshot behavior and origin independence | Reject |
| Snapshot prescribed reads once per occurrence, depth first | Array indices retain their positions; record getters run in observable own-key order. Wrong leaves fail where read | Rust aggregates support positional intuition; ECMAScript Get and own-property ordering govern dynamic reads, a deliberately closer analogy | Capture list length once; indexed load ICs and ordinary own-property traversal can specialize. No pre-scan duplicates user work | Records use own enumerable keys; lists Get indices 0 through captured length minus one, including nonenumerable/inherited indexed values. Named Array properties are outside the list. A missing value is undefined and fails admission. Getter effects remain subject to fragment rules; liveness is independent | Recommend independently of effort |

Record key lists are captured once, then each own descriptor is tested when visited and its value read once. Complete each child's snapshot before the next sibling read. Repeated references to the same acyclic child are separate occurrences: getters may produce distinct values, so pointer-identity memoization cannot skip reads. Mutation during traversal does not restart the snapshot. The ordinary effects of a throwing getter remain; failed metadata is not published.

## Cycles and portable work

| Direction | Ergonomics and autocomplete / wrong guesses | Prior art, including Rust | Production performance / shapes and ICs | Correctness and reference liveness | Other / decision |
| --- | --- | --- | --- | --- | --- |
| Recurse until host overflow or catch native RangeError | Error class and accepted depth vary by engine, making tooling unreliable | Rust checks constant evaluation with its own semantics; host stack capacity is not a language rule | Cheap source code, uncontrolled native capacity; no layout benefit | Does not implement logical limits or finite structural metadata | Reject |
| Reject every repeated object or memoize its first snapshot | Shared acyclic inputs fail or later getter observations vanish unexpectedly | Rust value sharing is not a precedent for skipping JavaScript observable reads | A global visited set is small but a result cache needs effect/identity proof | Confuses sharing with cycles or changes order/effects; grants no liveness | Reject |
| Track active ancestors and traverse with an explicit worklist under the shared meter | Cycles get a stable refusal and finite shared values remain usable | Rust's cycle/query discipline is a limited comparison; ECMAScript reads retain their specified order | Linear traversal work in visited occurrences, active-path storage proportional to depth, no object shape changes. Repeated occurrences are charged even if a production engine can reuse immutable representation | Cyclic containment is outside finite structural metadata; cleanup is local and the budget joins its caller. Limits cannot reset at children | Recommend independently of effort |

The snapshot accounts for one value visit and one container-advance or completion step at a time under the existing type-evaluation budget. Getters/helpers also pay their existing costs. The worklist avoids host recursion in snapshotting; it does not establish stack safety for every later normalization, comparison or materialization consumer. No budget or full convergence gate is closed by this repair.

## Retained Symbol-key and surrounding boundaries

Symbol values are admitted and preserve identity. Symbol-keyed record projection still loses keys elsewhere in the current interpreter's canonical representation, comparison and materialization paths; this increment does not claim to fix that defect. Stringification would collide unrelated Symbols, dropping them merges distinct types, and banning them would weaken the existing record-key contract. Choose identity-bearing keys across all canonical producers and consumers: useful computed-key completions, ECMAScript/Rust identity comparisons with their distinct models, compiler-owned maps rather than extra object shapes, exact equivalence and independent reference rules, and compatibility all favor that direction. Those rejected alternatives remain rejected regardless of implementation effort. Audit symbol-key records next as a complete path rather than changing only the snapshot producer.

Top-level flat-record admission, syntactic invalid-leaf projection, specialized range endpoint admission, Composite/array-view carriers and deep downstream traversal remain independent audit targets. Do not use these implementation gaps to expand the language or count a weaker runtime failure as the required static outcome.

Primary comparisons: [Rust constant evaluation](https://doc.rust-lang.org/reference/const_eval.html) (including its support for function paths and some closures, unlike this metadata language); [ECMAScript ordinary and exotic objects](https://tc39.es/ecma262/2025/multipage/ordinary-and-exotic-objects-behaviours.html). The recommendations above are this proposal's decisions, not claims that either prior art implements this metadata system.

Follow-up status: [Symbol metadata](symbol-metadata.md), [Symbol binding identity](symbol-binding-identity.md), and [metadata producer admission](metadata-producer-admission.md) address the historical Symbol, root-record and written-leaf failures above. Specialized range endpoints, carrier admission and deep downstream/resource accounting remain independent audits.
