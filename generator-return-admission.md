# Synchronous generator return requests

A generator's external `return(value)` request and a `return` executed by its body have different obligations. The external input is optional R, so omission and explicit `undefined` both pass. The body's written R remains strict. The generator operation result continues to use `GeneratorCompletionValue(R)` as described in generator-lifecycle.md.

This increment specifies and implements synchronous admission. Async requests retain their separately recorded queue/await design and remain the next task; the synchronous rule must not be inserted before an async enqueue or Await.

## Request admission and failure order

The intrinsic first validates the receiver, brand and non-executing state. It then admits a non-undefined payload against the R captured when this generator was created, using ordinary boundary admission, including its existing permitted conversions. The void input admits no non-undefined value merely because void completion results have a gradual discard view. An erased receiver, borrowed intrinsic method, completed generator and unstarted generator all retain the captured contract. Unknown or absent obligations retain their existing gradual behavior.

Admission precedes the request's state transition, body entry, cleanup and delegate lookup. A failed simple admission therefore leaves an unstarted or suspended generator available for a later valid request. This is not transactional rollback of user effects: ordinary admission can invoke a permitted converting constructor, conversion operator or property access. Such code can itself advance the generator. After successful admission, validate and read the current state again before applying the request. Validation errors precede admission effects; an admission error is propagated even if its own effects have changed state.

| Direction | Ergonomics / autocomplete | Prior art, including Rust | Real-engine performance | Correctness / liveness | Other / decision |
|---|---|---|---|---|---|
| Body-final enforcement only | Identical return calls differ before entry, during suspension and after completion. | Rust Coroutine has no external return method; it supplies no support for bypassing this JavaScript input. | Avoids an input check but leaves a false contract. | Misses unstarted/completed inputs; conflates omission with a body return. | **Reject.** |
| Validate payload before receiver/state | Can run a conversion on a call that could never resume; wrong guesses have unexpected effects. | Conflicts with ECMAScript's receiver/state validation order; Rust validates receiver capability structurally. | May do costly conversion for an invalid call. | Wrong failure precedence and effects. | **Reject.** |
| Validate once, admit, then reuse the old state | Looks simple until a conversion calls the same generator. | ECMAScript user conversions can re-enter; Rust exclusive access is a materially different constraint. | Saves one internal state read but can use a discarded context. | Stale state after admission effects is unsound. | **Reject.** |
| Lock the generator while checking or roll back conversion effects | Adds new errors or undoes visible work, despite no body resumption by this request yet. | Neither native JavaScript ordering nor Rust's static exclusivity implies a new runtime transaction. | Locks/rollback complicate reentrancy and invalidation. | Changes permitted effect order; rollback cannot generally restore arbitrary effects. | **Reject.** |
| Validate, admit optional R, validate current state, then resume | The displayed input contract applies in every state; bad inputs fail at the reached boundary. | Extends ECMAScript's lifecycle while preserving the Rust-like distinction between input and body return. | Ordinary admission plus an internal state reread; no wrapper or user-object shape change. | Captures stay attached to the generator; normal reference checks and effects remain in force. | **Recommend and implement**, independently of work required. |

## Completion provenance

An admitted external return is an internal completion associated with the generator that admitted it. Propagating that completion through a normal finally block, including one that yields and later resumes, does not make its payload a body return. A new return statement, abrupt finally block or other replacement completion does not inherit that association. The same `undefined` value in an explicit body return still fails a string body obligation. A second external return creates its own admitted completion. A failed second request does not erase the suspended first completion.

| Direction | Ergonomics / autocomplete | Prior art, including Rust | Real-engine performance | Correctness / liveness | Other / decision |
|---|---|---|---|---|---|
| Widen body R to include undefined | Hides body mistakes to accommodate valid external close. | Loses the separate Return contract that Rust's coroutine abstraction illustrates. | Simple but weakens useful checks. | Contradicts written body obligations. | **Reject.** |
| Exempt a value equal to the supplied payload | A finally return can accidentally gain permission because it returns the same primitive. | Neither ECMAScript completion flow nor Rust ownership associates authority with primitive equality. | Cheap comparisons, incorrect authority. | Equality cannot distinguish propagation from replacement. | **Reject.** |
| Keep one mutable “closing” flag per generator | Appears to work until nested finally yields, replacements or a failed second request. | Rust exclusive access does not justify this extra JavaScript lifecycle state. | Extra state transitions and cleanup on every exceptional exit. | Can excuse unrelated returns or lose an older suspended completion. | **Reject.** |
| Track the admitted completion and its owning generator | Omission works through cleanup, while a new body return keeps its own diagnostic. | Follows ECMAScript's completion propagation; Rust supplies only the separation-of-contracts analogy. | Can be an internal completion tag/owner; no result-object shape or IC change. The interpreter uses a weak association. | Propagation preserves provenance, replacements do not; no reference lifetime or read authority is granted. | **Recommend and implement.** |

## Delegation replaces a protocol result, not a body statement

When synchronous `yield*` receives an admitted external return and the delegate has no return method, it propagates that completion unchanged. When the selected return method produces a completed result, read done and value in the native order, then admit the replacement value against the enclosing generator's optional R and create a new external completion for that generator. This is an independent check even if the value equals the incoming payload. A delegate can replace the payload with a different admitted value, including undefined. Getter, call and admission failures follow the current body’s ordinary catch/finally path.

A non-completed delegate result is yielded normally. Subsequent normal resumption follows the native algorithm: it can finish the delegation normally and continue the body. A later explicit `return yield* delegate` is then a body return, with its own R obligation. This is why provenance cannot be attached permanently to the whole delegation or generator.

| Direction | Ergonomics / autocomplete | Prior art, including Rust | Real-engine performance | Correctness / liveness | Other / decision |
|---|---|---|---|---|---|
| Check every delegate replacement as strict body R | Closing nested string-returning generators without a payload fails, although every return input permits omission. | Rust has no corresponding replaceable return-forwarding protocol. | Reuses the body check at the wrong boundary. | Mistakes an external protocol response for an executed body return. | **Reject.** |
| Trust all delegate results or only preserve equal payloads | Custom delegates can inject an invalid value, or equal undefined receives special authority. | JavaScript lookup permits replacement; Rust's statically constrained receiver is not an equivalent guarantee. | Omits a needed guard or adds an unsound equality shortcut. | Fails erasure/replacement contracts. | **Reject.** |
| Propagate absent-method returns; independently admit completed replacements as optional R | Nested closes work; custom replacement mistakes fail at the reached protocol boundary. | Respects ECMAScript return forwarding; Rust remains only an analogy for separate channels. | One reached admission, ordinary result shape and method ICs; no wrapper. | Preserves effects, done-false behavior, body obligations and reference liveness. | **Recommend and implement.** |

These rules add no await, global binding or source type operator. They do not prove intrinsic identity from a method name, wrap an extracted method, make generator members readonly or allow a reference to escape its existing lifetime. Performance statements are design analysis, not measured engine results.
