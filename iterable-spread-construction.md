# Fresh iterable call-spread construction

A fresh Array used as a call spread has potential element destinations before its actual iterator runs. Contextual construction and actual protocol consumption are separate judgments:

```js
type Item = { fn: (value: string) => string }
          | { fn: <U: type>(value: U) => U };
function run(a: Item) { const fn: any = a.fn; fn.<number>(7); }
run(...[{ fn(value: U): U { return value; } }]);
```

The source method adopts the generic declaration supplied by its potential destination. When ordinary Array value iteration actually consumes that live data contribution, its selected alternative reaches parameter admission. The boundary cannot silently replace it with the overlapping nongeneric arm. The source Array does not acquire a tuple backing contract merely because its elements receive different construction contexts.

## Choosing source contexts

Project the potential source sequence onto the established signature without executing values. Concatenate finite fresh Array-literal positions and direct arguments, counting elisions as positions. Apply explicit-name pinning and the existing fixed/rest destination rules. Homogeneous Array rests supply their element type; determined tuple rests supply effective positions after substitution, including finite runs and required suffixes. Preserve declaration identity, captured arguments and callable views. A reference destination has no fresh value context.

This projection is conditional on sequential index consumption. It does not assert that an installed iterator yields those positions, yields that count, or succeeds. A custom hook may consume, reorder, replace or ignore source elements; it sees the values as constructed, and the actual call keeps its ordinary binding and checks. No iterator is pre-run or replayed to obtain a context. Completion can show the potential element contract while making no promise about a mutable protocol. Unavailable correspondence supplies no guessed neighbour's type.

## Capturing actual consumption

The producing completion owns the selected children. A temporary capture belongs to one actual built-in Array-value iterator resumption over that same source. Read the current index through the normal iterator operation, validate the producing data descriptor and every nested contribution, and retire only the consumed source-index edge. Later replacement of that outer slot cannot alter the already captured argument. Nested replacement remains relevant at admission. Same-value replacement before capture invalidates the source association.

Match the iterator's actual source and read index. A custom iterator-producing hook may return the original Array value iterator, even after advancing it. A next-method getter may return the native operation; its lookup still runs once and its mutations precede capture. Built-in bound forwarding remains transparent: follow its immutable target/receiver records to the actual native resumption, with inner bound receivers taking precedence. A user next wrapper, Proxy call, custom generator or iterator result returning the same value gains no source selection. Built-in keys/entries modes do not contribute the source child itself. A native iterator over a different Array also gains no selection from value equality.

The interpreter registers native next implementations across realms and scopes capture to the actual iterator receiver, including bound forwarding. It records the first native value read for that step, clears the frame in a finally path, and transfers the eligible internal completion to the argument occurrence. It stores no pending selection on the public iterator-result object. Nested independent operations retain their own contexts. The selected member is checked at the ordinary receiving boundary, with no fallback on failure and no change to the union storage contract or reference lifetime.

## Coverage and remaining scope

Coverage includes functions, arrows and methods in both union orders; fixed and homogeneous/tuple rest parameters, required suffixes, multiple fresh spreads, direct prefixes/suffixes, named pinning, elisions, empty sources, constructors, callable views, explicit specialization, captured aliases and imports. Controls cover identity and numeric positions, source order, mutation before/after capture, nested mutation, custom hooks/next/generators, bound forwarding, other sources, skipped indices, getter counts, abrupt iteration/arguments, selected failure, reentry and recovery. Module, Script, eval, Function and feature-off surfaces are included.

This increment implements finite fresh source sequences without nested source spreads and the existing declaration-proved fixed/rest partitions. Unknown-length nested source spreads, value-dependent multiple-rest/optional partitions and unresolved/alternative tuple domains still require separate coverage under the same chosen design. It does not grant a choice to arbitrary iteration or stored values. Assignment receiving boundaries remain the preserved required-success queue; full body/default applicability, rollback, diagnostic reuse and broader convergence remain open gates.

The recommendation is an inference from these mechanisms and the proposal's existing construction/liveness commitments; Rust has neither this gradual structural admission nor mutable JavaScript protocol lookup.
