# Numeric range scaling and reflection

`scale(factor)` and unary range negation preserve the range's endpoint domain and each endpoint's own numeric type. They operate on the interval, independently of the item carrier used by iteration. This audit replaces Number narrowing, unchecked integer arithmetic, and the former split between ordinary and rational-factor scaling.

## Required outcomes

- Retain the original stored or inferred domain, including unions, and every endpoint's numeric family and width. Autocomplete must not promise a typed endpoint that runtime erases.
- Interpret every finite real numeric factor exactly. Do not coerce objects or strings, or take a complex value's real component.
- Integer and rational results are exact and representable; floating bounds enclose the exact mathematical image. Do not wrap, truncate or silently invent an infinite endpoint on overflow.
- Specify empty, identity, zero, negative, omitted-bound and explicit-infinity behavior, including endpoint representation and admission order.
- Publish only after required admissions succeed. Never mutate the source or grant a reference capability. Hook effects retain their ordinary semantics.

The built-in numeric contract covers `number`, `bigint`, sized signed and unsigned integers, binary `float16`/`float32`/`float64`/`float128`, decimal32/64/128, rational types, and their numeric metadata parameterizations. A stored union of these domains is retained without selecting a common arithmetic carrier. `any` is permitted when the actual endpoints are supported. Other ordered types need their own scalar multiplication contract; ordering alone does not supply one.

## Representability and rounding

| Direction | Ergonomics | Prior art, including Rust | Production performance | Correctness | Other / decision |
|---|---|---|---|---|---|
| Apply ordinary scalar wrap/truncation/round-to-nearest | Familiar operators, but the resulting interval can omit the exact value its bounds are meant to describe. | Rust checked and wrapping arithmetic are distinct choices. Boost requires inclusion for interval results. | Fastest arithmetic; does not buy correctness. | Wrap reverses order; truncation and nearest rounding can shrink the image. | **Reject.** Scalar conversions keep their existing rules. |
| Saturate to finite extrema or invent infinity on overflow | Avoids throws but hides loss and changes finite/infinite reflection. | Saturating integers exist in Rust, but are explicitly named and do not specify interval scaling. | Cheap saturation on some platforms; extra result cases. | Saturation can exclude the image; infinity would alter the selected failure and representation contract. | **Reject.** |
| Require exact representability in every family | Predictable errors, but a floating singleton scaled by 1/3 has no usable result despite adjacent enclosing floats. | Exact rational arithmetic fits this rule; floating interval libraries deliberately use outward rounding. | Representability tests can use exact fallback; no directed output needed. | Sound but unnecessarily partial for intervals. | **Reject as the floating rule.** |
| Exact integers/rationals; outward floating bounds | Integers throw on a fractional result or overflow; floating results may widen and moved bounds become closed. | Rust `checked_mul` supports visible integer overflow. Boost's inclusion property and directed rounding are the closer floating analogy; Boost's intervals are closed, whereas this proposal also preserves exact open bounds. | Fixed two-edge work, native directed rounding where available, exact fallback otherwise. No range shape mutation or enumeration. | Exact image is enclosed while numeric domains and admission remain checked. | **Recommend.** |

For a nonzero factor, compute the mathematical product without an intermediate Number conversion. An integer result must be integral and in range. A rational result is reduced and must fit its existing numerator/denominator contract. Failure throws RangeError.

For each binary or decimal floating endpoint, use the nearest representable value **outward in its final endpoint role**: lower toward negative infinity, upper toward positive infinity. If rounding moved the endpoint, close its bound; otherwise retain the original bound. Finite products beyond the format's greatest finite magnitude throw RangeError, even if an inward rounded value would fit. Binary subnormals participate, including signed zero. Decimal nonzero products below the base's supported minimum adjusted exponent throw RangeError; this does not introduce a new decimal subnormal format. A nonzero binary product rounded to zero retains its mathematical sign. Zero multiplied by a nonzero factor uses the ordinary sign product.

For example, `(1..=1).scale(rational64(1,10))` has Number bounds `0.09999999999999999..=0.1`. A float16 singleton at 1 scaled by 1/10 has bounds `0.0999755859375..=0.10003662109375`. An open bound that moves outward becomes closed: the operation returns a conservative enclosure, not necessarily the smallest set obtainable with every bound convention.

Metadata `rescale` hooks that call `bounds.scale(f)` inherit this enclosure rule. A Number factor written `0.001` is its actual binary value, not the exact decimal fraction 1/1000. Scaling `100..=500` can therefore extend above 0.5, so admission to exactly `0.1..=0.5` is not justified. This change does not alter ordinary scalar `ScaleMetadataValue`, which still applies its own conversion/rounding rules.

## Empty, identity, zero and infinity

| Direction | Ergonomics | Prior art, including Rust | Production performance | Correctness | Other / decision |
|---|---|---|---|---|---|
| Multiply all endpoints even for empty, identity and zero cases | Can overflow an empty range, rerun hooks on unchanged values, or turn a half-open range into an empty zero result. | Rust ranges do not define these arithmetic shortcuts; mathematical images determine empty/zero cases. | Unnecessary arithmetic and admission callbacks. | Loses empty/zero image semantics and representation identity. | **Reject.** |
| Skip all validation on fast exits | An invalid factor works only for certain bounds; autocomplete cannot describe that contract. | Rust type checks do not disappear for empty runtime values. | Slightly fewer guards; surprising conditional acceptance. | Inconsistent operation availability. | **Reject.** |
| Validate first, then copy empty/identity; construct one admitted zero for nonempty zero scaling | Wrong input always fails; unchanged values retain zero signs, decimal cohorts and metadata without repeated hooks. | Consistent with typed operation boundaries and mathematical images; details are specific to this API. | Fixed guards; no edge arithmetic on copies, one admission for zero. | Preserves source and liveness; result published after admission. | **Recommend.** |

Validate receiver, numeric domain and endpoints, then factor. Then test emptiness; an empty input is copied, including its crossed endpoints and bounds. Exact +1 also copies. Exact zero (either sign) on a nonempty input produces a closed singleton at canonical positive zero. Select that zero's type from a concrete numeric stored domain, otherwise original start's type, otherwise original end's type. Only an endpoint-free `any` range defaults to Number. An endpoint-free union has no determined zero carrier and throws TypeError. Arbitrarily choosing a union member is rejected because declaration ordering would select runtime representation; returning a union of alternative values is not a scalar endpoint; converting every zero to Number breaks domain identity. Rust has no union-endpoint precedent; the selected fixed tag rules preserve specialization and need no new range shapes.

Explicit infinite endpoints stay present and change sign for a negative factor; omitted bounds stay omitted. A negative factor swaps endpoint roles and their bounds after calculation/admission. Treating infinity as absence is rejected because reflection distinguishes them. For emptiness in the extended numeric order, `Infinity<..` and `..<-Infinity` are empty: nothing is strictly beyond either extreme. Closed extreme one-ended ranges remain nonempty singletons. Retaining the previous “every missing-bound range is nonempty” rule contradicts membership and makes zero scaling invent an inhabitant. Treating every extreme as empty instead loses the closed singleton. Rust's partially ordered floats do not decide these custom open-start forms. The selected intrinsic infinity test has constant cost and no comparison callbacks or liveness effects.

## Admission and decimal representation

| Direction | Ergonomics | Prior art, including Rust | Production performance | Correctness | Other / decision |
|---|---|---|---|---|---|
| Strip metadata or trust the old endpoint's admission | Results can claim constraints violated by the new value. | Rust primitive arithmetic has no direct analogue of these user-defined validation hooks. | Fewer hooks but invalid type promises. | Breaks checked admission. | **Reject.** |
| Permit admission to rescale or requantize a computed endpoint | An apparently successful scale can move the bound inward or change units twice. | Neither Rust checked arithmetic nor interval inclusion supports arbitrary post-computation movement. | Reuses conversion but loses numeric guarantees. | Can break enclosure, zero sign and decimal representation. | **Reject.** |
| Admit each new endpoint, require unchanged computed representation, publish last | Failure is visible and the source remains reusable; earlier hook effects still occur. | Extends explicit checked arithmetic with this proposal's metadata boundary; no claim of rollback from Rust or Boost. | At most two admissions, normal hook dispatch, fixed result layout. No transaction journal. | Preserves types, exact image/enclosure and reference-liveness rules. | **Recommend.** |

Compute and admit the **original start first, then the original end**, even when a negative factor reverses their final roles. Propagate the first failure immediately. Reordering into result order is rejected because it reverses observable hook effects; attempting both after failure adds effects; rollback would need a new transactional language feature. Source order follows ordinary evaluation expectations, adds no production overhead, and has no direct Rust range-arithmetic precedent. Result publication occurs after both succeed. Admission may attach the promised full numeric parameterization, but it may not change the computed numeric value, binary zero sign, or decimal coefficient/exponent; such changes throw RangeError. Existing hook exceptions propagate unchanged.

Identity copies preserve decimal cohorts. Exact reflection preserves the coefficient/exponent representation while negating the coefficient; other decimal products use the reduced coefficient/exponent of the directed result. Always reducing identity/reflection is rejected because ordinary unary reflection preserves useful representation; inventing a preferred precision for arbitrary rational factors is rejected because it is not supplied by the input. Rust has no built-in decimal cohort rule. This explicit rule is deterministic, preserves existing reflection expectations, uses fixed metadata checks, and has no effect on reference authority. The current decimal model has no separate signed-zero slot.

## Construction and remaining scope

Range construction must recognize the intrinsic ordering of real float128, decimal and rational values; their object-backed interpreter representation does not require a user `operator<`. Rejecting them until they declare an operator confuses storage with numeric semantics. Coercing them through Number loses precision. Accepting every numeric object would include unordered complex values and NaN. The selected intrinsic classification admits finite real values and infinities and rejects NaN/complex values; it reads no public properties. This matches typed ordering principles in Rust, while this proposal uses total ordered endpoints. It adds only tag guards, keeps shapes stable and grants no reference permissions. Existing mixed plain BigInt construction restrictions are not generalized by this repair and need the separate mixed-domain audit.

Binary interval `+`, `-`, `*`, `/`, custom arithmetic domains, complete static scaling/adapter result typing and extended-family iteration remain separate work. The legacy binary interval code still narrows wide endpoints through Number. This increment does not claim closure of the broader checking, inference or regression gates.
