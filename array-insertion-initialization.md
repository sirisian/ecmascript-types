# Initialization for indexed growth and insertion

This extends [explicit length initialization](array-growth-initialization.md) to indexed growth and to `unshift`/growing `splice`. A supplied value is checked at its actual backing type. Newly exposed positions without supplied values need their own defaults. No requested growth is published until its new positions are initialized.

The constraints are: preserve the actual backing type and fixed/suffix survivor rules; never publish a new uninitialized tail; permit inserting supplied values of non-defaultable types; preserve callback order and independent effects; make failed growth and reference invalidation agree; retain ordinary untyped Array behavior. A mutation plan is not permission to overwrite reentrant changes.

## Direct skipped-index stores

| Direction | Ergonomics | Prior art including Rust | Real-engine performance | Correctness | Other and recommendation |
|---|---|---|---|---|---|
| Reject every skipped index | Predictable failure, but the existing growable-array API would have two inconsistent growth spellings | Rust Vec indexing does not grow; this proposal deliberately exposes growth by assignment | Constant-time guard | Safe, but unnecessarily excludes defaultable gaps already supported by length growth | Rejected: avoid an arbitrary distinction between `length = n` and a supplied final element |
| Expose holes or implicitly optional positions | Indexed reads/autocomplete promise T while a wrong guess yields undefined | JS holes are real; Rust's initialized prefix is the opposite model | Hole checks and optional layouts weaken dense storage and IC assumptions | Violates existing typed backing and references | Rejected; an explicit optional/hole type would be a separate feature |
| Fill gaps with a universal raw zero or undefined | Numeric examples hide failures for classes, strings and non-defaultable types | Neither language supplies a universal valid value for all types | Cheap clearing but invalid representations | Does not satisfy the actual element contract | Rejected; use the type's real default |
| Initialize gaps from their actual defaults and retain the supplied destination | Matches existing zero-fill expectations; non-defaultable gaps give a precise error | Rust separates explicit initialization from spare capacity; the syntax and borrowing model differ | O(gap) writes; pure primitive defaults can bulk-fill dense storage with stable element contracts | Supplies all new positions, copies values as required, and rejects missing defaults before publication | Selected independently of implementation effort |

The supplied value's existing boundary conversion occurs before gap-default computation. Defaults then run in increasing index order. The complete new tail and the destination's requested descriptor are published together using the length-growth publication rules. A failed store must not change capacity or allocation generation merely because its index was large. An inherited setter that consumes the value without adding an own element likewise causes no growth or relocation.

## New descriptors without values

| Direction | Ergonomics | Prior art including Rust | Real-engine performance | Correctness | Other and recommendation |
|---|---|---|---|---|---|
| Use ordinary implicit undefined for every new property | Familiar reflection defaults, but numeric storage silently receives a nonnumeric value | This is JS's untyped descriptor rule; Rust has no direct property-descriptor counterpart | Cheap initialization with the wrong representation | Unsound for typed storage | Rejected |
| Reject every omitted value | Clear but forces callers to spell a default the type already provides | Rust requires initialized values; it does not determine this reflective API | Cheap guard | Safe but needlessly rejects defaultable positions | Rejected |
| Use the actual type's default for an omitted value | Aligns omitted initialization across typed positions; explicit undefined still crosses normally | Default initialization is the relevant analogy, not JS's implicit undefined | One default computation for the new property; descriptors retain ordinary attribute defaults | Creates a typed data value without erasing caller-specified flags | Selected; an existing property's omitted value still means retain its value |

A new accessor property does not supply an initialized data slot and is rejected. This concerns creation of a new own typed element, not conversion of an existing property into an accessor. The latter's ongoing read/reference contract is a separate audit. Nonextensibility and length writability refuse creation before missing defaults are computed. Filling a missing own element inside an existing extent follows the same default rule, with a reentry check that preserves any independently created replacement. This is defensive handling of existing sparse state; it does not endorse creating that state.

## Creating a new accessor element

| Direction | Ergonomics | Prior art including Rust | Real-engine performance | Correctness | Other and recommendation |
|---|---|---|---|---|---|
| Treat accessor presence as initialization | A key exists, but a getter can return an incompatible value or no value; autocomplete still advertises the backing type | JS allows accessor properties; a Rust reference requires an actual location | Requires calls and potentially generic shapes instead of dense element storage | Does not establish initialized backing or an invariant reference location | Rejected |
| Invoke the getter now and store its result, or validate every later read | Invoking now changes descriptor semantics; later validation makes apparently typed reads fail unpredictably | Dynamic property hooks have no direct Rust Vec counterpart | Eager effects, or recurring checks and callbacks on reads/IC paths | Eager invocation loses the requested accessor; read checks alone do not define writable reference storage | Rejected for owned typed data positions; an explicit virtual-property model would require separate semantics |
| Reject creation of a new accessor element | A precise definition-time failure identifies that no data location was supplied | Consistent with requiring actual storage rather than a computation | A descriptor-kind guard preserves dense backing and stable IC assumptions | Preserves the initialized-data and reference-location requirements | Selected independently of effort; existing accessor replacement remains a separate known gap |

## Growing intrinsic insertions

A naive application of gap defaulting to every internal store breaks function arrays: `unshift(f, f)` writes the old last element to a high index before supplying lower new positions. Those gaps will receive values; they do not need function defaults.

| Direction | Ergonomics | Prior art including Rust | Real-engine performance | Correctness | Other and recommendation |
|---|---|---|---|---|---|
| Require defaults for transient internal gaps | The same supplied function values work with push but fail with unshift; autocomplete gives no reason | Rust insertion does not require Default | Simple reuse of direct growth | Preserves initialized storage but rejects valid supplied-value insertion | Rejected |
| Publish holes temporarily and repair or roll back later | Getters can observe invalid typed positions; later failure can leave them behind | Ordinary JS permits holes; Rust does not expose uninitialized Vec elements | Cheap writes followed by complex cleanup | Repair cannot undo observed holes, callbacks or invalidated references | Rejected |
| Prefill the tail before ordinary movement | Callbacks observe invented intermediate values and a larger length before the operation reaches its ordinary writes | Initialized storage is possible, but exclusive mutation analogies do not justify reordered JS effects | Can bulk-fill, but may duplicate writes/conversions and allocate temporary values | Preparing moved values or defaults early reorders getters/conversions; supplied values cannot justify arbitrary filler types | Rejected as observable semantics; a proved effect-free implementation may still fuse work |
| Prepare and replace the entire operation atomically | Strong transaction-like appearance, but suppresses existing partial writes and changes what callbacks see | Exclusive Rust mutation avoids these JS observations; it does not supply rollback semantics | O(array length) staging, descriptor/callback replay problems, potentially extra shape changes | Can be made safe only with broader changes to existing effects | Rejected: stronger mutation semantics than initialization needs |
| Keep only new tail definitions private until final publication | Callbacks see the previously published extent; existing-position writes and failures remain ordinary | Initialized-prefix reasoning applies; callback visibility remains a new JS-specific rule | O(growth) staging, no new receiver shape; dense pure paths may fuse movement and publication | Supplied values need no defaults; missing tail values still require defaults; no partial new extent escapes | Selected; preserve all independently executed effects |

After the ordinary receiver/length/index processing and existing backing-plan validation, a growing owned typed Array insertion records its current length and backing. The ordinary algorithm's property reads, conversions, species work and setters keep their order. Its own data definitions at new tail indices are retained privately. Reads, keys and reference acquisition see only published storage. Writes within the recorded extent occur immediately and remain if later work fails.

Only a particular intrinsic write can stage a definition. Code invoked by a getter, setter, species constructor or conversion performs independent writes, even to the same array and same index. Nested mutations do not join the outer insertion. The implementation scopes staging to the intrinsic write's receiver, property key and execution context, and restores that scope in a finally block.

Before and after each insertion write, and before publication, a changed published length, backing contract or fixed extent rejects the stale outer insertion. Recheck after lookup/conversion effects and before the resulting own definition, including when a callback has created that very destination; checking only after the write would overwrite independent work. Earlier abrupt completions keep their ordinary precedence. Existing value writes alone do not cancel the plan. Changes to capacity alone are retained and current capacity is used at publication. A default callback during final preparation receives the same conflict checks as explicit length growth.

At final publication, positions actually supplied by successful own data definitions use those prepared descriptors. A setter that consumes a value without defining the tail position has not initialized it; that position needs its default, or publication throws. No inherited setter runs again. Recheck descriptor compatibility and extensibility before publishing the tail, final length and any required relocation without intervening user code. Failure discards private definitions; it does not undo existing-element writes or independent effects.

## Scope and follow-up

Direct and reflected indexed growth, omitted-value definitions, growing owned typed Array unshift/splice, and publication-based capacity accounting are covered. Ordinary untyped arrays and nongrowing intrinsic paths retain their behavior. Fixed extents and suffix survivor constraints remain prior checks. General proxy/array-like backing and unsupported tuple sequence shapes are unchanged.

The larger no-holes audit still needs direct deletion, sparse incoming admission, and existing accessor replacement/read/reference rules. Those are distinct ways to damage existing storage, not permission to weaken new-tail initialization. Retain concrete follow-up witnesses and evaluate each new decision under all five criteria. No full conformance gate is closed by bounded passing tests.

Primary references: [Rust Vec guarantees and insertion](https://doc.rust-lang.org/std/vec/struct.Vec.html), [ECMAScript unshift](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.unshift), and [ECMAScript splice](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.splice). Rust's exclusive borrowing limits the callback analogy; ordinary JavaScript alone does not provide the typed initialization invariant.
