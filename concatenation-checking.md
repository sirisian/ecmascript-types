# Concatenation result typing and checking phases

On an established built-in `+` concatenation path, the normal result is `string`. A String literal type, a current flow refinement to one, a union containing only String types, or a wrapper over String provides the same category fact as a plain `string` annotation. Parentheses do not change it. This is a fact about a successful result, not a guarantee that coercion cannot throw.

For example, `let s:string="a"; let n:uint8=1; let r:uint8=n+s;` is rejected before the Script body runs. The concatenation produces String and the destination requires uint8; a contextual destination cannot reinterpret the operation as addition or parse its result. The same judgment feeds assignment, return, argument and member/element destinations.

Read String category proofs through literal bases, metadata and shared/reference wrappers, enum underlying types, and established type-parameter bounds. A nonempty union needs the proof for every member; an intersection can use a member that already restricts every inhabitant to String. An unresolved type or recursive revisit supplies no proof. This descriptor query neither evaluates a conversion nor erases the operand's actual type, brand, participation or reference permissions. Existing lexical constant evidence may supply a String literal; an unannotated mutable initializer does not become a permanent contract.

Declared dispatch precedes the built-in result. A selected class operator or primitive block can return another type. An open left operand can carry its own operator even when the right operand is known String. Likewise, failure to select a primitive block for an entire compound operand contract is not proof that no member can select one. Preserve an established selected result, and defer an unresolved result rather than replacing it with String. This does not weaken parameter admission or the operation's existing conversion failures.

## Verification boundaries

The proof-of-concept uses one shared expression-result judgment, with Script, generated Function and importing Module cases, ordered getter/conversion effects, and same-realm recovery after a rejected Script. Feature-off JavaScript retains ordinary concatenation. Deep wrapper and compound-type probes prevent repairing only the original binding spelling.

The String category query has invocation-local recursion tracking and no arbitrary trial-depth cutoff. It does not close general recursive formation, portable budgets, or primitive-block resolution. Compound block alternatives without an established single result remain conservative. The pre-existing gaps for an unannotated constant copied through another constant or read from a later Script (including an annotated constant) remain recorded; a local literal constant test does not certify general constant provenance. A String-receiver primitive-block execution probe still falls through to concatenation and needs a validity/dispatch audit; an admission-only control does not certify that runtime path. Numeric equality participation and the older computed-key/flow-refinement expectations also remain separate audits.

Primary references: [Rust Add](https://doc.rust-lang.org/std/ops/trait.Add.html) and [ECMAScript ApplyStringOrNumericBinaryOperator](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-applystringornumericbinaryoperator). Rust's trait-based dispatch is an analogy for selected output contracts, not a replacement for this proposal's coercion, metadata or reference rules.
