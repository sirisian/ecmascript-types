# Accessors and owned Array storage

Owned typed Array elements are data locations. A reflective definition cannot replace one with an accessor, even when the accessor's current result has the expected type, the element type is `any`, or the old data descriptor is configurable. The attempted definition throws `TypeError`. Named properties and non-index keys keep ordinary accessor behavior. Ordinary untyped Arrays and object properties are unchanged.

```js
const a: [].<uint8> = [7];
const raw: any = a;
Object.defineProperty(raw, "0", { get() { return 9; } }); // TypeError
// a[0] remains 7; an existing element reference still names that data location.
```

When an untyped Array reaches a boundary that would acquire owned sequence storage, remaining own accessors refuse admission. Membership reads happen first, with their existing effects and abrupt completions. After successful membership and combined length-domain planning, preflight own descriptors before materializations and writes. Do not silently replace an own accessor, invoke its setter to make it storage, or infer a permanent contract from one getter result.

The descriptor judgment is about current storage, not the input's history. A getter may independently replace itself with matching own data; if the retained length, presence and value checks then pass, that data can be admitted. Conversely, an accessor installed by a later materialization callback must prevent publication. Revalidate all planned positions as data before publishing missing elements or new contracts, including when a callback independently acquired backing.

## Storage decision

| Direction | Ergonomics | Prior art, including Rust | Real-engine performance | Correctness | Other and decision |
|---|---|---|---|---|---|
| Trust the getter's admitted result forever | Autocomplete promises T while a later read can return an unrelated value; wrong guesses fail far from the mutation | Ordinary JS accessors can vary; Rust Vec elements are stored values, not callbacks | Cheap initial check, but unsound typed loads and IC assumptions | A single result proves neither initialized backing nor future reads | Rejected |
| Permit only accessors whose getter/setter contracts are independently enforced | Typed accessor authors can participate, but ordinary equivalent getters fail; autocomplete still hides callback storage | Typed methods can enforce returned values; Rust custom indexing is closer than Vec storage | Typed calls may inline under guards, but still require descriptor/callback representation and deoptimization instead of uniform element layout | Can protect value contracts with descriptor-change checks; does not make a computed property an owned data location | Rejected for owned arrays; existing custom index operators express computed access separately |
| Permit accessors only for any or non-layout element types | The same definition changes legality when an element type is refined; wrong guesses complicate gradual aliases | Ordinary JS Array is permissive; Rust reference-valued Vec still stores elements | Splits representations and IC assumptions by element kind; wider views must preserve that distinction | any relaxes value checking, not the proposal's owned-storage and location commitments | Rejected; no implicit representation opt-out through any |
| Retain accessors and check every read and write | Live getters remain usable; every indexed read can now fail or run arbitrary code | JS ordinary accessors are the close analogue; Rust Vec's contiguous storage is not | Requires a descriptor-aware representation and callback/check slow paths, with shape and IC invalidation; contiguous layout cannot uniformly apply | Can enforce returned-value contracts, but does not establish the proposal's owned data layout or ordinary stored-value/reference model | Rejected for owned arrays; a distinct computed/indexed abstraction is a separate feature |
| Replace configurable own accessors with retained data | Admission silently stops a live getter; aliases and ordinary property borrows observe changed behavior | JS descriptor configurability permits an explicit replacement, not a request to snapshot at a parameter boundary; Rust has no equivalent descriptor | One-time rewrite can recover dense storage, but changes shapes and must resolve missing setters and permissions | Could provide data, but conflicts with ordinary accessor-preserving materialization and cannot handle nonconfigurable inputs uniformly | Rejected; users can explicitly copy values |
| Copy every accessor-bearing input automatically | Convenient snapshot, but the accepted parameter no longer aliases its input | JS spread/Array.from express copying; Rust conversion to a new collection also owns a new destination | Allocation and element copies on otherwise compatible admission | Violates identity-preserving compatible admission; complicates reference expectations | Rejected; retain genuine elementwise conversion and explicit copies |
| Require own data when acquiring or maintaining owned storage | An immediate boundary/definition error identifies the incompatible representation; autocomplete's element type remains a stored-value contract | Rust Vec and JS integer-indexed TypedArray storage support the data-only analogy; their exact index and error rules differ | Preserves unboxed/contiguous fast paths; descriptor checks occur at acquisition and mutation, without new per-read calls or receiver bookkeeping properties | Matches layout, initialized extent, invariant locations, and liveness commitments | Selected independently of implementation effort |

`[].<any>` still establishes owned element storage; `any` as the receiving type alone does not. A readonly data element remains data and can be admitted without changing its attributes. The rule applies equally to homogeneous arrays, fixed extents, and tuple positions. A tuple's unresolved general sequence representation is not an exception to the data requirement.

Inherited accessors are different: the receiver has no own location there yet. The existing sparse-admission procedure may use their admitted values to initialize missing own data, preserving identity and custom prototypes. It does not replace the inherited descriptor. Required changed-value materialization still uses ordinary Set and can invoke an inherited setter or encounter getter-only refusal. Pure `is` queries remain observational and may succeed for an accessor-bearing source without making it valid owned storage.

An explicit compatible cast still follows identity-preserving admission and can therefore refuse. An actual elementwise conversion that needs a new Array produces data and leaves its source accessors alone. To request a snapshot irrespective of compatibility, copy explicitly, for example `[...source]`, then admit that dense Array. No constructor or conversion API is introduced here.

## Admission phase decision

| Direction | Ergonomics | Prior art, including Rust | Real-engine performance | Correctness | Other and decision |
|---|---|---|---|---|---|
| Reject descriptors before membership reads | Fast refusal, but suppresses getters and changes which exception is seen | Rust can inspect storage without JS hooks; that is not this proposal's ordinary membership procedure | Can avoid work, but needs a different observable admission path | Changes existing read order, failed alternatives, and abrupt precedence | Rejected |
| Reject after materialization writes | Setters run even though their accessor cannot be admitted | JS ordered effects are possible, but no Rust analogy justifies knowingly unusable storage work | Executes avoidable conversions, copies and callbacks | Eventually safe if final validation is complete, but needlessly changes state before a predictable refusal | Rejected |
| After membership and length-domain planning, before materialization, then revalidate | Existing getters retain their order; predictable representation failure precedes setter work | Fallible preparation before publication is analogous to initialized storage construction; JS effect timing is specific | Descriptor scan shares existing sparse preflight/final validation; engines can use equivalent dependency guards | Preserves selected evidence, membership errors, earlier effects, and no partial new publication | Selected |
| Reject only on the first later indexed read | Failure moves away from the admitting call and autocomplete's promise | Neither Vec nor a stored TypedArray element becomes a deferred getter check | Adds read guards and leaves invalid backing published | Does not establish owned storage at the boundary | Rejected |

Preflight is not a new membership alternative. Once a union alternative has been selected, a representation refusal is an abrupt boundary failure; it does not try another alternative. An earlier throwing getter retains its exception. A failed admission publishes none of its new contracts or pending missing positions. Earlier getter effects and independently completed boundaries survive.

## Reflective refusal decision

| Direction | Ergonomics | Prior art, including Rust | Real-engine performance | Correctness | Other and decision |
|---|---|---|---|---|---|
| Return false for the typed-storage prohibition | Reflect.defineProperty callers can test it, but unchecked callers can silently miss an invariant failure | Existing integer-indexed TypedArray definitions can return false; Rust has no reflective descriptor API | Cheap branch | Could protect storage, but differs from the proposal's existing typed deletion and accessor-growth TypeErrors | Rejected for the type prohibition |
| Throw TypeError at the reached storage check | Object and Reflect spellings report the same type-contract failure | Follows this proposal's runtime invariant errors; does not copy TypedArray's exact return convention | Cheap definition-path guard; no read-path overhead | Retains the data and live references, including through any aliases | Selected |
| Silently ignore the accessor or keep a hidden data slot beside it | Reflection and reads disagree, with no useful signal to the caller | Neither JS descriptors nor Rust stored elements imply this dual behavior | Extra representation state and divergent IC paths | Ambiguous read/write/reference authority | Rejected |

Ordinary key and descriptor conversion occurs before the internal definition, and its effects or exceptions retain precedence. Existing fixed-extent/tuple-domain checks and the ordinary nonwritable-length refusal for growth retain their order. Thus a growth attempt can still return false at the earlier length check before reaching this prohibition. A reached indexed accessor prohibition throws even for a nonconfigurable current data descriptor. `Object.defineProperties` retains earlier successful definitions before a later refused accessor. Generic/data descriptor updates keep their existing rules and attributes. Independently acquired object-property contracts still constrain an otherwise untyped Array; propagate their existing definition refusals as language exceptions.

## Reentry and references

| Direction | Ergonomics | Prior art, including Rust | Real-engine performance | Correctness | Other and decision |
|---|---|---|---|---|---|
| Treat an initially valid descriptor as a lease | A callback can install an accessor after preflight and still obtain typed backing | JS permits reentry; Rust excludes overlapping mutable access rather than trusting stale descriptors | Fewer checks, invalid typed-load assumptions | Publishes incompatible storage | Rejected |
| Reject any Array that ever had an accessor, or invalidate every borrow on refusal | Independent repair to data cannot succeed; a failed mutation unexpectedly destroys a live reference | Rust borrowing is not descriptor-history tracking; ordinary JS has no such history rule | Requires history/generation state and new invalidation paths | Stronger than current-state backing requirements and existing lifetime rules | Rejected |
| Validate current descriptors at preflight and publication; refusal changes no location | Independent matching data can be admitted, conflicting changes remain visible, and existing references keep their locations | Consistent with stored-element reasoning; JS effects and runtime liveness use this proposal's own rules | Reuses descriptor scans; no new receiver shape or history lease | Preserves backing, earlier effects, and removal/relocation identity rules | Selected |

The general property-borrow rule remains: an ordinary accessor property can be borrowed, reads call its getter, and writes call its setter. It does not authorize a descriptor forbidden by the receiver's storage contract. Refusing data-to-accessor replacement changes neither length, capacity, data, nor element identity. A live element reference remains live, subject to independent effects that may already have removed or relocated storage. Named properties on typed Arrays retain ordinary accessor-location behavior.

## Verification scope and remaining work

The previous tests intentionally characterized unresolved own-accessor behavior. Admission-effect tests now use inherited accessors, retaining reads, materialization, copies, setter receivers, failures, and independently acquired backing. Once those values become own data, later compatible views do not call the prototype getter again. Twenty-five mutation-order tests that require accessors already inside typed backing are preserved as explicit legacy host fixtures. Their setup bypasses the Array descriptor guard only in the test harness; they are not language conformance examples. Public conformance separately checks that the setup is refused. The migration ledger in the delivery records every change and its reason.

This resolves the owned-Array descriptor policy, not the complete structural-object accessor system, general proxy/array-like backing, general reentrant adoption, or the remaining tuple sequence representations. No broad conformance gate is closed by this bounded increment.

Primary references: [Rust Vec guarantees](https://doc.rust-lang.org/std/vec/struct.Vec.html) and [ECMAScript integer-indexed DefineOwnProperty](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-integer-indexed-exotic-objects-defineownproperty-p-desc). Neither Rust's borrow checker nor TypedArray's numeric/index/error conventions are imported wholesale.
