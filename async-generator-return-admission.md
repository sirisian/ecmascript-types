# Async generator return requests

An async generator keeps the protocol captured at creation. Its external return input is optional R after native assimilation; its body return remains a separate strict R obligation. Omission and explicit undefined pass the input, while void does not admit another resolved payload. The completed operation result still includes exhaustion. Erasure, a borrowed intrinsic, completion and generic captures do not remove an established protocol.

## Admission stages and failure state

Keep native receiver/brand validation, enqueue, state transitions and Promise scheduling. Never await or admit the operand before enqueue. At a suspended yield, AsyncGeneratorUnwrapYieldResumption first performs its native Await; admit the fulfilled value against optional R. A failed admission is the throw resumption of that yield. It can be caught, yield another value, run finally or reject the current request. A valid return bypasses catch, as before.

For an unstarted or completed generator, and during queue draining, AsyncGeneratorAwaitReturn first performs native Promise resolution. Its fulfillment reaction admits the resolved value. On failure, reject that queue-head request and continue draining; on success, complete that request with the admitted value and continue draining. Existing PromiseResolve failures and rejected reactions retain their native paths. The unstarted body is not entered, even if admission fails. The request's earlier state transition is not rolled back.

Permitted conversions can enqueue requests on the same generator. Keep the current request at the head until admission completes. Later requests cannot overtake it. Conversion, getter and thenable effects are not transactional. Promise rejection reasons win over admission because rejected values are not admitted.

## Raw signature and resolved obligation

The optional raw `AsyncGenerator<Y,R,N>.return` input is the canonical union of direct R (undefined for void), `Promise<any,any>`, and a structural object with a callable `then` accepting the ordinary resolver/rejector arguments. Any remains gradual. This is the existing typed Promise resolver model, not a guarantee that a thenable fulfills with R. Nested thenables and Promises can be supplied; their eventual value crosses the runtime R boundary. A known incompatible direct scalar or plain object remains a static error. A Promise with an incompatible fulfillment type is a valid raw request that can reject; unknown objects are not all declared thenable.

This contract travels through the generator member's ordinary function type. It does not depend on a call spelled `.return`, make the member readonly, bind an extracted method, or give a replacement method intrinsic identity. Structural iterator declarations keep their written input contracts; the generator accepts their direct input and adds native assimilable requests. No general signature equivalence is added.

## Completion provenance and delegation

Associate an admitted completion with its generator, as for synchronous requests. Await and normal finally propagation do not make it a body return. A fresh body return, fallthrough or abrupt replacement retains its ordinary obligation; identical undefined values do not transfer permission. A failed second request at a yielding finally is a throw resumption and can replace the pending return: unlike synchronous pre-resumption rejection, the generator has already reached an async admission stage.

Preserve native async yield-star ordering. With no return method, keep the native additional Await and admit its actual result, retaining external provenance. For a selected return method, await the result object, validate Object, read done, then read value. A done-true replacement value is independently admitted against optional R **without another Await**. ECMAScript does not await that property here. A Promise-valued property is therefore an object payload, not its eventual fulfillment. Async-from-sync delegation retains the adapter's own assimilation. A done-false result follows ordinary yield/resume processing; a later body return is fresh.

| Direction | Ergonomics / autocomplete | Prior art, including Rust | Real-engine performance | Correctness / reference liveness | Other / decision |
|---|---|---|---|---|---|
| Treat delegate replacement as body R | Nested omitted closes fail; errors arrive outside the delegate boundary. | Rust has no equivalent replaceable return-forwarding protocol. | Reuses the wrong check. | Confuses protocol response with body statement; can add body-return assimilation. | **Reject.** |
| Await every done-true value | Familiar async intuition, but executes a then getter where native yield-star does not. | ECMAScript awaits the result object here; Rust Future does not recursively inspect an output for then. | Extra suspension/jobs and guards. | Changes effects, payload identity and reference invalidation. | **Reject.** |
| Skip provenance/admission, or attach a closing flag | Omissions sometimes work, but replacements and later body returns can gain permission. | Neither native completion flow nor Rust ownership authorizes values by equality or a global flag. | Fewer guards at the cost of unsound state; extra flag cleanup on exceptional paths. | Loses captured obligations and propagation/replacement distinction. | **Reject.** |
| Keep native awaits, admit each reached external replacement, preserve completion ownership | Native object/thenable behavior is observable; mistakes fail at the reached boundary and catches can handle them. | Follows ECMAScript; Rust supports only the separation-of-contracts analogy. | No extra suspension, wrapper or result-object shape; ordinary admission and internal owner/tag. | Preserves cleanup, payload identity and existing reference liveness. | **Recommend and implement.** |

All performance statements are design analysis, not benchmarks. General function/callback context transport is a separate gap: these rules enforce an established captured protocol and do not manufacture one from mutable caller spelling.
